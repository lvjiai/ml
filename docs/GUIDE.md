## 1. 先用一句话说清项目

> 给一台正在运转的发动机（或任何设备）一段传感器读数，估计"它还能再撑多少个周期"，并且给一个范围，说明这个估计有多不确定。

三个关键词：

| 词 | 意思 | 在本项目里 |
|---|---|---|
| **RUL** | Remaining Useful Life，剩余寿命，单位是"周期"（一次起降/一天运行算一个周期） | 模型要预测的数 |
| **点预测** | 只给一个数，比如"还剩 47 个周期" | GBDT 的输出 |
| **区间** | 给一个范围，比如"[38, 56]，有 90% 的把握真值在里面" | CQR / split conformal 的输出 |

为什么区间重要：维修决策不是"换不换"，而是"**现在换、还是再飞一班**"。只给一个数，维修班组没法判断该不该信；给了区间，才能看出"这个 47 可能是 38，也可能是 56"。

## 2. 必备概念（外行版）

### 2.1 数据长什么样

C-MAPSS 是 NASA 公开的涡扇发动机退化仿真数据。每一行是"某台发动机在第几个周期时，21 个传感器各读到了多少"：

```
unit  cycle  setting_1  setting_2  setting_3  s_1   s_2   ...  s_21
1     1      34.998     0.840      100.0      518.67 641.82 ...  23.41
1     2      34.998     0.840      100.0      518.67 641.82 ...  23.36
...
```

- `unit`：第几台发动机（训练集共 709 台）
- `cycle`：第几个运行周期
- `setting_1..3`：三个运行设定（油门、高度、马赫数之类）
- `s_1..s_21`：21 个传感器的读数

训练集的每台发动机都是"**从头跑到坏**"，所以能算出它每个周期还剩多少寿命；测试集是"跑到一半就断了"，只给最后一个周期的真值标签。

### 2.2 回归

回归 = 预测一个连续的数（不是分类的"是/否"）。这里的数是 RUL。

模型就是一个函数：`f(传感器读数) → 剩余寿命`。训练就是调整这个函数的参数，让它在训练数据上错得少。

### 2.3 三个数据集，三种用途

| 名字 | 占比 | 用来干什么 | 能不能反复看 |
|---|---|---|---|
| 训练集（fit） | 训练发动机的 80% | 学参数 | 可以 |
| 校准集（calib） | 训练发动机的 20% | ① 校准区间 ② 选模型 | 可以，但只用于这两件事 |
| 测试集（test） | 官方给的测试发动机 | 最终打分 | **只读一次** |

关键：测试集不能用来调参。一旦用它调过参，报出来的分数就是"作弊后的分数"。我们早期犯过这个错（FD001），后来在 W18 补了严格流程。

### 2.4 数据泄漏

泄漏 = 训练时不小心看到了"未来"或"答案"，导致分数虚高。本项目有三处容易泄漏：

1. **按行随机切分**：同一台发动机的相邻周期几乎一样，随机切会让训练集和测试集"共享"同一台机器 → 必须**按发动机切**。
2. **用了考核成绩/未来数据**：我们的特征只用当前及以前的周期（因果），不用未来。
3. **用测试集调参**：见上。

### 2.5 为什么把 RUL 截断在 125

一台发动机能活 300 个周期。在第 1 个周期，"还剩 299"没有实际意义——反正还早，维修班组不关心。文献惯例是把超过 125 的一律当成 125：

```
真实 RUL = 299  →  训练目标 = 125
真实 RUL = 47   →  训练目标 = 47
```

好处：模型把精力集中在"临近失效"的区间，那里才是决策相关的地方。代价：模型学会"很早就报 125"，这是后面"卡平台"问题的根源之一。

**注意**：截断必须在三处一致——训练目标、区间上下界、评估真值。我们曾经只在训练截断、评估不截断，导致 FD002/FD004 的分数虚高约 10 个点（W12 修正）。

## 3. 数据是怎么变成模型输入的

### 3.1 读取与校验

原始文件是空格分隔的文本，没有表头。`src/data/loader.py` 负责：

1. 读进来，补上列名；
2. 校验每台发动机的 `cycle` 从 1 开始、每次加 1（用 `_check_cycles`）；
3. 校验行数与官方文档一致（`validate`）：FD001 训练 20,631 行、测试 13,096 行，等等。

为什么校验行数：数据文件被截断或换版本时，行数会变。行数不对，后面所有结论都不可信。

### 3.2 按发动机切分

`split_units(units, frac=0.8, seed=42)` 把发动机编号打乱后切两半：80% 进训练集，20% 进校准集。

- 打乱用固定种子 42，保证每次跑结果一样；
- 切的是**发动机编号**，不是行——同一台机器的所有周期只会出现在一边。

### 3.3 训练标签怎么算

`add_rul(df, clip=125)`：对每台发动机，`RUL = 这台机器最后一个周期 − 当前周期`，再截断到 125。

例：某台机器活到 200 周期。第 50 周期时 `RUL = 200 − 50 = 150 → 截断成 125`；第 180 周期时 `RUL = 20`。

### 3.4 测试标签怎么来

测试集只给"最后一个周期"的位置，标签在 `RUL_FD00x.txt` 里（每台一个数）。要评估"每周期"表现时，先反推失效时刻：

```
失效时刻 F = 最后观测周期 + RUL_FD00x 里的值
第 t 周期的真值 = min(F − t, 125)
```

这就是 `scripts/w13_per_cycle.py::failure_times` 做的事。

### 3.5 演示时"观测窗口"是什么意思

演示里拖动滑杆 = 假装"我们只看到了前 N 个周期"。程序把轨迹截到第 N 个周期（`observable_window`），再让模型预测。所以滑杆越往右，模型看到的信息越多，预测通常越准。

## 4. 技术词典

本章按"数据 → 模型 → 区间 → 评估"的顺序排。每项技术给四段：**直觉**（外行版一句话）、**怎么算**（能看懂的最小公式）、**本项目**（用在哪、什么参数、代码位置）、**注意**（坑或局限）。

### 4.1 标准化（z-score）

**直觉**：把不同传感器拉到同一把尺子上。温度是几百、压力是几十，不换算的话，数值大的传感器会"霸占"模型的注意力。

**怎么算**：`x' = (x − 均值) / 标准差`。变换后每个传感器均值 0、标准差 1。

**本项目**：放在"工况归一化"里做（4.2），按每个工况分别算均值和标准差；只在训练集上拟合，测试/演示数据沿用同一套均值方差。代码 `src/features/conditions.py:54-64`。

**注意**：如果某个传感器在训练集里几乎不变（标准差≈0），除以 0 会炸；代码里把这种标准差强制设为 1（`conditions.py:50-51`）。

### 4.2 工况聚类（KMeans）

**直觉**：同一台机器在"巡航"和"爬升"时，同一个温度传感器会读出差很多的值。先按运行设定把数据分成几堆（工况），再在每堆内部做标准化，才能把"设备老化"和"今天飞得猛"区分开。

**怎么算**：KMeans 反复做两件事——① 随机放 K 个中心点；② 每个样本归到最近的中心，再把中心挪到该类样本的平均位置；重复到不动为止。

**本项目**：`ConditionNormalizer`（`src/features/conditions.py`），在 3 个运行设定上聚类，`N_CONDITIONS = {FD001:1, FD002:6, FD003:1, FD004:6}`（官方说明里 FD002/FD004 就是 6 种工况）。聚类中心在训练集上拟合，输出多一列 `condition`（0..5）。

**注意**：条件数 K 是"先验写死"的，不是自动选的；K 选错会让归一化把有用信号也抹掉。

### 4.3 滚动窗口特征

**直觉**：单看一个瞬间的读数说明不了退化，要看"最近 10 个周期的平均在往哪走"。就像看体温，不看一次，看趋势。

**怎么算**：对每个传感器、每个窗口 w（5/10/20/30 个周期），算四个量：

| 特征 | 公式 | 含义 |
|---|---|---|
| `_mean_w{w}` | 最近 w 个周期的平均 | 当前水平 |
| `_std_w{w}` | 最近 w 个周期的标准差 | 抖动多大 |
| `_diff_w{w}` | 当前值 − 窗口平均 | 偏离平均多少 |
| `_trend_w{w}` | (当前值 − w 个周期前的值)/(w−1) | 平均每周期变化多少（斜率） |

另外每个传感器还有一个 `_cummax`（历史最大值）——退化往往表现为"再也回不到从前"。

**本项目**：`src/features/rolling.py:15` `add_rolling_features`。21 个传感器 × 4 窗口 × 4 统计 = 336 列，+21 个 cummax +21 个原始值 +1 个 condition = **379 列**（`artifacts/features_FD001.json` 可核对）。

**注意**：这些统计只用"当前及以前"的行（因果），所以对截断的测试轨迹同样合法——这是没有数据泄漏的关键。

### 4.4 线性回归与 Ridge

**直觉**：最简单的一把尺子——假设 RUL 是各特征的加权和，学出权重。Ridge 在权重上加了"别太大"的惩罚，防止过拟合。

**怎么算**：最小化 `Σ(y − w·x)² + λ‖w‖²`，有闭式解。

**本项目**：作为基线（`ridge_raw` 用原始传感器，`ridge_engineered` 用 379 维特征），证明"树模型确实比线性模型强，但不是靠特征工程一个因素"。

**注意**：线性模型无法表达"温度高到一定程度才危险"这种阈值效应，所以对退化数据天然吃亏。

### 4.5 决策树

**直觉**：一连串"是/否"问题。比如"最近 10 周期温度平均 > 0.8 吗？→ 是 → 再看振动趋势……"，走到叶子就给出一个预测值。

**怎么算**：每次挑一个特征和切分点，让切完两边"各自内部尽量像、彼此尽量不像"（最小化平方误差）。递归切到满足停止条件。

**本项目**：LightGBM 的每一棵树都是这种树（但叶子值是"残差的拟合值"）。单棵决策树没有单独跑过，它是一个可以 1 分钟补上的基线。

**注意**：单棵树很容易记住训练数据的噪声（过拟合）；所以要用几百棵（4.6）。

### 4.6 梯度提升树（GBDT）与 LightGBM

**直觉**：接力纠错。第一棵树粗粗预测；第二棵树专门学"第一棵错在哪"；第三棵再学"前两棵合起来还错在哪"……几百棵加起来，误差被一层层削掉。

**怎么算**：从常数 `F₀` 开始，每轮拟合损失对当前预测的负梯度（对平方损失就是残差 `y − F`），乘学习率加上去：`F ← F + η·h_t`。η 是学习率（本项目 0.05），小一点更稳但需要更多树。

**本项目**：`src/models/gbdt.py`。`DEFAULT_PARAMS`：`learning_rate=0.05, num_leaves=31, min_data_in_leaf=50, feature_fraction=0.8, bagging_fraction=0.8`。树的棵数由分组交叉验证选（4.8）。

**注意**：LightGBM 是"按叶子生长"的，`num_leaves` 一大就很容易过拟合小数据（FD003 只有 100 台机器时尤其明显）。

### 4.7 树的超参数与早停

**直觉**：树太多会把噪声也学进去，太少又学不够。早停 = 在验证集上盯着，连续若干轮不再变好就停手。

**怎么算**：每轮在验证集算 RMSE；若连续 `early_stopping` 轮（本项目 100 轮）没有刷新最好成绩，就回到最好那一轮。

**本项目**：`train_gbdt(..., num_boost_round=3000, early_stopping=100)`；但在正式选型里用 `select_model`（4.8）对两组超参 `{31,50}` 与 `{63,20}` 做 3 折分组交叉验证，上限 1500 轮，取 CV 平均 RMSE 最低的组合。四个子集最终都选中 `{31,50}`。

**注意**：早停的验证集必须是"模型没见过的发动机"，否则等于偷看答案。

### 4.8 分组交叉验证（GroupKFold）

**直觉**：把训练集切成 3 份，轮流拿 2 份训练、1 份验证。"分组"的意思是：同一台发动机的所有周期必须整组待在同一边。

**怎么算**：按发动机编号分组，`GroupKFold(n_splits=3)` 保证每组只出现在训练或验证一侧。

**本项目**：`select_model`（`src/models/gbdt.py:82`）。选的是"超参 + 树棵数"，只用训练发动机，测试集不参与。

**注意**：如果按行随机切，同一台机器的相邻周期几乎一样，验证分数会虚高得离谱。

### 4.9 线性树（linear_tree）——负结果

**直觉**：让每个叶子不是一个常数，而是一条小线性模型，理论上能拟合"平滑退化"。

**本项目**：`gbdt_linear_tree`（`lambda_l2=1.0, min_data_in_leaf=100`）。结果不稳定：FD001 略好（17.25 vs 17.40），FD003 明显变差（19.26 vs 15.60），FD002/FD004 也没赢。**未采用**。

**注意**：小数据上叶子里的线性模型参数太多，容易过拟合；这是"看起来更聪明、实际更差"的典型。

### 4.10 专家混合（MoE）——负结果

**直觉**：6 种工况各训一个专家模型，预测时先判断工况再交给对应专家。

**本项目**：`moe`（按 `condition` 分专家，某工况训练单元 <8 台就退回全局模型）。只有 FD004 略好（28.16 vs 28.78，NASA 4934 vs 5686），其余持平或更差；而且这个 FD004 增益是在测试集上看到的，不能作为选型依据。**未采用**。

**注意**：分专家会让每个专家看到的数据更少，小数据下通常不划算。

### 4.11 神经网络基础

**直觉**：一层层做加权求和 + 非线性变换，把输入"揉"成越来越抽象的特征，最后输出一个数。训练 = 反复微调权重，让输出更接近答案。

**怎么算**：前向 `h = 激活(Wx + b)`；损失 `L`；反向传播用链式法则算 `∂L/∂W`；优化器按梯度更新权重。

**本项目**：PyTorch 实现，CPU 训练。LSTM 与 ConvTransformer 两个网络（4.12–4.16）。

**注意**：神经网络对输入尺度敏感，所以进网络前一定要标准化（4.1）。

### 4.12 序列窗口化

**直觉**：网络要吃"最近 30 个周期"的一小段，而不是一整条长度不一的轨迹。这样每条样本尺寸固定。

**怎么算**：滑窗切片，第 t 个样本是 `[t−29, t]` 的 30×传感器矩阵，标签是第 t 周期的 RUL。

**本项目**：`src/models/lstm.py:27` `build_sequences`（窗口 30 步长 1，因果）；测试/演示只有一条截断轨迹时，`last_window` 取最后 30 行，不足 30 行就在左端重复第一行补齐。

**注意**：补行会引入轻微偏差，但比"拒绝预测"实用；短轨迹（<30 周期）时置信度天然更低。

### 4.13 LSTM

**直觉**：带"记忆"的序列模型。它一边读序列，一边维护一个记忆单元，决定"记住什么、忘掉什么"。

**怎么算**：每个时间步用三个门（遗忘门、输入门、输出门）控制信息流：

```
f = σ(W_f·[h, x] + b_f)      遗忘多少旧记忆
i = σ(W_i·[h, x] + b_i)      写入多少新信息
o = σ(W_o·[h, x] + b_o)      输出多少
c ← f ⊙ c + i ⊙ tanh(...)    更新记忆
h ← o ⊙ tanh(c)              更新隐藏状态
```

**本项目**：`RULNet`（`src/models/lstm.py`）：LSTM(21→64) → Linear(64→32) → ReLU → Linear(32→1)。训练用 Huber 损失（4.17）、Adam 学习率 1e-3、batch 128、最多 40 轮、早停 patience 6，取验证集最好的权重。

**注意**：LSTM 对窗口长度很敏感——本项目窗口 30 与 50 的测试排名就不一样（见第 8 章 W14）。

### 4.14 一维卷积

**直觉**：拿一个小"放大镜"在时间轴上滑动，每次看相邻几个周期，提取局部模式（比如"连续 3 个周期温度都在涨"）。多个放大镜叠加，视野逐层变大。

**怎么算**：`y[t] = Σ_k w[k]·x[t + d·k]`，d 是膨胀率（dilation）。d=1 看相邻点，d=2 隔一个看，d=4 隔三个看——不增加参数就能看更远。

**本项目**：ConvTransformer 的前置层，3 层膨胀卷积（dilation 1/2/4）+ LayerNorm，先把 30 个周期压成 30 个"局部摘要"，再交给注意力层。

**注意**：卷积本身不区分时间先后，位置信息要靠后续的位置编码补。

### 4.15 自注意力与 Transformer

**直觉**：让序列里每个位置自己去"看"其他位置，决定该关注谁。比如临近失效时，模型可能同时关注"温度在涨"和"振动在抖"这两段。

**怎么算**：`Attention(Q,K,V) = softmax(QKᵀ/√d)·V`。Q/K/V 都是输入乘不同权重得到的；多头就是并行做几组，关注不同侧面。

**本项目**：`ConvTransformer`（`src/models/deep.py`）：卷积摘要 → 可学习位置编码 → 2 层 `TransformerEncoder(d=64, 4 头, FFN 128, norm_first)` → 注意力池化 → 拼工况嵌入 → MLP 输出。训练：AdamW lr=1e-3、余弦退火、batch 256、30 轮、多种子平均。

**注意**：Transformer 参数多，小数据上必须靠早停、dropout、多种子来压方差；本项目的深模型在末周期很强、在中段却显著变差（见第 8 章 W17）。

### 4.16 注意力池化与工况嵌入

**直觉**：序列有 30 个位置，最后要压成一个向量。普通做法是取最后一个或用平均；注意力池化是"学一个权重，决定每个位置该占多少分量"。

**工况嵌入**：把工况编号（0..5）变成一个可学习的向量，拼进特征里，让网络知道"现在是哪种运转状态"。

**本项目**：`deep.py` 的 `pooled = (attn_weights * H).sum(dim=1)`，再 `torch.cat([pooled, cond_emb], dim=1)`。

**注意**：嵌入只对"离散类别"有意义；FD001/FD003 只有 1 种工况，这一维实际是常数。

### 4.17 损失函数：MSE 与 Huber

**直觉**：MSE 对"错得离谱"的样本惩罚特别重（平方），Huber 在误差小的时候像 MSE、误差大的时候像绝对值，不会被个别离群点带偏。

**怎么算**：

- MSE：`(y − p)²`
- Huber（δ=10）：`|e| ≤ δ` 时 `0.5e²`，否则 `δ(|e| − 0.5δ)`

**本项目**：GBDT 用 L2（默认）；LSTM 与深模型用 Huber δ=10——因为 RUL 误差偶尔会出现几十的离群值。

**注意**：Huber 的 δ 是超参，太小退化成 MAE（收敛慢），太大退化成 MSE（怕离群点）。

### 4.18 优化器与学习率

**直觉**：梯度只说"往哪走"，学习率决定"走多大步"。步子太大会来回震荡，太小要跑很久。

**本项目**：GBDT 用 LightGBM 内置的 boosting；LSTM 用 Adam（1e-3）；深模型用 AdamW（1e-3）+ 余弦退火（学习率按余弦曲线从 1e-3 慢慢降到接近 0）。

**注意**：学习率是最影响结果的一个超参，改它之前先固定别的。

### 4.19 多种子与 TTA

**多种子**：同一套结构用 3 个不同随机种子各训练一次，预测取平均。目的是抵消"这次初始化运气不好"。

**TTA**（Test-Time Augmentation，测试时增强）：把输入窗口向左/右平移 −2..+2 个周期，各预测一次再平均。目的同上，但不用重训。

**本项目**：深模型用 3 种子；LSTM 与深模型在 W14/W15 都加了 TTA（平移 −2..+2，共 5 个副本）。收益：LSTM 约 0.5–1.0，深模型约 0.5。

**注意**：TTA 假设"平移一点点，答案不该变"，这在退化末期成立，但在突变点附近会引入偏差。

### 4.20 等权集成

**直觉**：几个模型各自犯错的地方不一样，平均一下能互相抵消。

**本项目**：`lstm_w50 + deep`、`gbdt + lstm` 等等权平均（不学权重，避免再拿测试集调参）。结果：末周期平均从 15.2 降到 13.3 左右，但中段（60–80% 寿命）反而没有优势。

**注意**：等权是"最保守"的集成；学权重要额外的验证数据，本项目数据量不够，容易过拟合。

### 4.21 分位数回归

**直觉**：普通回归学"平均值"，分位数回归学"90% 的样本会低于哪个值"。学两个分位（5% 和 95%），就得到一个粗略的区间。

**怎么算**：把损失换成 pinball loss：`ρ_τ(e) = max(τ·e, (τ−1)·e)`。τ=0.05 时模型倾向低估，τ=0.95 时倾向高估。

**本项目**：CQR 的两个"底座"就是两个 LightGBM 分位数模型（`objective="quantile", alpha=0.05/0.95`，400 轮），特征与主模型相同。

**注意**：分位数模型在小数据上容易"交叉"（低分位预测反而高于高分位），所以代码里最后强制 `lo ≤ point ≤ hi`（`pipeline.py:198-200`）。

### 4.22 split conformal

**直觉**：先看模型在"校准集"上错多少，然后把"典型错误幅度"当成安全余量，加在预测两边。

**怎么算**：

1. 在校准集上算绝对误差 `s_i = |y_i − p_i|`；
2. 取第 `k = ceil((n+1)(1−α))` 小的 `s`，记作 `q`；
3. 区间 `[p − q, p + q]`。

理论保证：只要校准集和测试集"同分布"，真实值落在区间里的概率至少 `1−α`。

**本项目**：`src/intervals/conformal.py:24` `conformal_quantile`；α=0.1（90% 区间）。作为 CQR 的对照。

**注意**：`q` 是在校准集上算的，**换分布就失效**——这正是 W5 的核心发现：换工况后覆盖率从 0.86 掉到 0.39，而宽度一动不动。

### 4.23 CQR（Conformalized Quantile Regression）

**直觉**：分位数回归给了一个"可能太窄/太宽"的区间，CQR 再用校准集把它"校正"到刚好覆盖 90%。

**怎么算**：

1. 校准集上算 `E_i = max(q_lo,i − y_i, y_i − q_hi,i)`（区间没盖住真值多少）；
2. `Q = E` 的第 `ceil((n+1)(1−α))` 小；
3. 最终区间 `[q_lo − Q, q_hi + Q]`，再截断到 `[0, 125]`。

比 split 的好处：区间宽度可以随样本变化（不确定大的地方自动变宽）。

**本项目**：主方法（α=0.1）。实测：覆盖率 0.86–0.96，宽度 42–55 周期；**但没有比 split 更窄**（每档宽 3–6 周期），原因写在 `docs/reports/W4.md`：低 RUL 段点模型已经很准、分位模型低估不确定性、校准点只有 291–761 个。

**注意**：CQR 的保证是"边际覆盖"——平均看是 90%，但不保证每个 RUL 段都 90%。

### 4.24 覆盖率与区间宽度

**覆盖率**：真值落在区间里的比例。目标 90%，实测 0.86–0.96。

**宽度**：区间平均有多宽（周期数）。宽度越小、覆盖率越高越好，但两者此消彼长。

**条件覆盖**：按 RUL 分段看的覆盖率。本项目 0–30 段、30–80 段、80–200 段分别算（`interval_metrics`）。

**注意**：只报覆盖率不报宽度是耍流氓——把区间做成 [0,125] 覆盖率永远 100%。

### 4.25 RMSE、MAE 与 NASA 分

**RMSE**：`sqrt(mean((p−y)²))`，单位与 RUL 相同，对大误差敏感。本项目主指标。

**MAE**：`mean(|p−y|)`，对离群点不敏感，用来补充。

**NASA 分**：文献常用，非对称——**预测偏晚（p>y）罚得更重**：

```
d = p − y
d < 0（预测偏早）: exp(−d/13) − 1
d ≥ 0（预测偏晚）: exp( d/10) − 1
总和即分数，越小越好
```

**本项目**：`src/eval/metrics.py`。注意：在"每周期"口径下 NASA 分动辄数万，不适合横向比较（W13 记录）。

**注意**：不同论文的截断、评估位置不同，RMSE 不可直接横比（见第 9 章）。

### 4.26 分段 MAE 与每周期评估

**分段 MAE**：把测试样本按真实 RUL 分成 `[0,30)`、`[30,80)`、`[80,200]` 三段，各算 MAE。这样能看出"模型是临近失效准、还是远处准"。

**每周期评估**：不只评估测试轨迹的最后一个周期，而是对轨迹上每个周期都算一次真值（`min(F−t,125)`）并打分。

**本项目**：W13 `per_cycle`（late 视图 = 只看后半段；all 视图 = 全轨迹）、W17 中段评估（60/65/70/75/80% 寿命五个位置）。

**注意**：早期周期的真值恒为 125（因为截断），误差自然小——这不是模型准，是标签平。

### 4.27 bootstrap 与配对检验

**bootstrap**：有放回地重抽发动机（比如 2000 次），每次重算指标，看指标的波动范围。95% 区间 = 2.5% 与 97.5% 分位。

**配对**：两个模型用同一批重采样算差值，抵消"这台机器本身难"的共同因素。

**本项目**：`scripts/w16_blend_final.py`、`scripts/w17_midlife.py`。结论示例：末周期 `lstm_w50 + deep` 比 `w50` 低 0.50，但区间 [−0.88, +0.14] 跨 0 → **不显著**。

**注意**：bootstrap 只反映"换一批机器会怎样"，不包含训练种子/划分的波动；不要把它当成"一切不确定性"。

### 4.28 选型协议与后悔值

**问题**：如果拿测试集挑模型，报出来的分数一定偏乐观。

**协议**（W18）：每台校准发动机截断在 75% 寿命，得到 142 个"伪测试点"；8 个候选模型只在校准集上比 RMSE，选中后测试集只读一次。

**后悔值**：`选中模型的测试 RMSE − 事后最优模型的测试 RMSE`。本项目平均 13.65，事后最优 13.24，后悔 0.41。

**注意**：校准集只有 20 台机器（FD001）时，选型本身噪声很大。

### 4.29 Streamlit

**直觉**：用 Python 直接写网页，不用学前端。改了代码刷新页面就生效。

**本项目**：`app/streamlit_app.py`，单页：选场景 → 选机器 → 拖观测窗口 → 看指标卡与两张图。所有预测只调 `src.pipeline.predict_one`，保证演示与实验同一条路径。

**注意**：Streamlit 每次交互会重跑整个脚本，所以耗时的加载要用 `@st.cache_resource` 缓存。

### 4.30 pytest

**直觉**：把"应该成立的事实"写成代码。以后改代码，跑一遍就知道有没有改坏。

**本项目**：48 个测试，覆盖数据校验、特征因果性、树/网络前向、conformal 覆盖、pipeline 端到端、demo 上传解析。`python -m pytest -q` 一条命令跑完。

**注意**：测试要快（<1 分钟），所以用合成小数据；真数据只在少数集成测试里出现。

### 4.31 子进程编排、缓存与随机种子

**子进程编排**：`scripts/run_all.py` 按 W1→W5 顺序起子进程跑脚本，任何一步失败就停。好处是"一键复现"，坏处是中间结果靠文件传递。

**缓存**：演示里 `@st.cache_resource` 缓存模型与数据，避免每次点按钮都重新加载 45 MB 数据。

**随机种子**：所有随机过程（切分、KMeans、树、网络初始化、bootstrap）都固定种子（42 为主）。报告里的数字因此可复现。

**注意**：固定种子 ≠ 结果稳定；换种子后的小幅波动要靠 bootstrap 或多种子来估计。

## 7. 一次完整推理的逐步追踪

以演示页"场景 4、第 24 台、观测到第 121 周期"为例：

1. **读数据**：`get_dataset("FD004")` → `load_subset` 读训练集完整轨迹（249 台）。
2. **截断**：`observable_window(df, 24, 121)` → 只保留第 24 台 cycle ≤ 121 的行。
3. **补列**：`build_features` 发现缺 `unit/cycle` 就补；`bundle.norm.transform` 按工况标准化 21 个传感器。
4. **造特征**：`add_rolling_features` → 每行 379 列（窗口 5/10/20/30 的均值/标准差/偏离/斜率 + cummax + 原始值 + condition）。
5. **取末端**：`last_cycle_rows` → 只留第 121 行。
6. **点预测**：`booster.predict(x)` → 例如 115.2，再 clip 到 [0,125]。
7. **区间**：`q_lo.predict(x) − Q` 到 `q_hi.predict(x) + Q`，clip 到 [0,125]，并强制包含点预测（示例 [60.8, 125]）。
8. **对真值**：真值 = `min(失效时刻 − 121, 125)`。如果勾了"显示真实值"，页面把真值（或 `≥125`）与误差一起显示。

这条路径**和实验脚本完全一致**——所以演示里的数字不会和报告里的数字打架。

## 9. 常见问题与坑

**Q1：为什么不用随机森林/XGBoost？**
LightGBM 是 GBDT 的一种高效实现，效果与 XGBoost 同档；随机森林是"并行 bagging"，通常略弱于 boosting。选 LightGBM 主要是因为 CPU 上快、支持分位数目标（CQR 要用）。

**Q2：为什么 FD002/FD004 明显比 FD001 差？**
FD002/FD004 有 6 种工况，同一个传感器读数在不同工况下含义不同。做了工况归一化能缓解（W5 的 E3），但不能完全消除。

**Q3：为什么模型在中段会"卡平台"？**
训练标签把 >125 截成 125，平台期样本占大多数（大部分周期离失效还远）。模型学到"看起来正常 → 报 115 左右"，等到真正开始退化时反应慢。这是 W17 的核心发现，也是当前最大的短板。

**Q4：为什么 CQR 没有比 split conformal 更窄？**
低 RUL 段点模型已经很准（0–30 段 MAE 7.4），分位模型在这个区间低估不确定性；校准点只有 291–761 个，分位数估计本身的噪声就不小。见 `docs/reports/W4.md`。

**Q5：为什么说"换工况后区间不可信"？**
区间宽度只由校准集决定，换分布后模型误差变大、但 Q 不变（宽度恒 48.2），覆盖率就从 0.86 掉到 0.39——"静默失效"。

**Q6：RUL 大于 125 时怎么办？**
模型上限就是 125。演示里超过 125 的现实值显示为 `≥125`，误差按 125 计，并明确标注"模型上限 125"。

**Q7：为什么不按行随机切分？**
相邻周期几乎重复，按行切会让训练集和测试集共享同一台机器，分数虚高。

**Q8：为什么报告里的分数比论文低/高？**
口径不同：评估位置（末周期 vs 全周期）、是否截断 125、测试集是否被用来调参、是否用 TTA。横比之前先对齐口径。

**Q9：这个项目能直接上工业现场吗？**
不能。只有仿真数据、没有真实故障、没有在线推理与告警闭环；定位是"方法与评估协议"，不是产品。

**Q10：怎么最快跑起来？**
`pip install -r requirements.txt` → 把 C-MAPSS 放进 `data/cmapss` → `python scripts/run_all.py --fast`（约 30 秒）→ 双击 `打开demo.bat`。
