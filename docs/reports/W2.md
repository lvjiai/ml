## 2. 做了什么

1. **按工况归一化**：FD001/FD003 单工况，直接 z-score；FD002/FD004 用三个 setting 聚成 6 类，再在类内对每个传感器 z-score。目的是消除"同一读数在不同工况下含义不同"的伪信号。
2. **滑窗特征**：窗口 5/10/20/30，每个传感器算 `mean / std / diff(x−mean) / trend(首尾斜率)`，另加 `cummax`、原始值、settings、condition，共 379 维。全部向量化实现，FD004（6.1 万行）特征构造约 2 秒。
3. **因果性**：把某台发动机的轨迹截断到第 80 周期后重算特征，与全量结果逐列比对，确认没有任何特征偷看未来（`test_rolling_features_are_causal`）。
4. **模型选型**：在训练单元内部做 GroupKFold(3)，网格 2 组超参 × 早停，选 CV 最优；四个子集都选中 `num_leaves=31, min_data_in_leaf=50`，轮数 73–119。

> 选型只用训练单元；测试集在 W2 里只用于报告，符合 FR-2.5。

## 3. 结果（测试单元末周期，RMSE / NASA score）

| 子集 | W1 `ridge_raw` | GBDT+特征 | Ridge+特征 | 50/50 融合 |

**RMSE 相对 W1 基线下降 20–31%，四个子集全部改善。**

## 4. 三件值得记住的事

1. **特征比模型重要**：同一套 379 维特征，Ridge 从 22.44 → 16.34（FD001），GBDT 从 22.44 → 17.40。特征带来的增益大于换模型。
2. **GBDT 不是全胜**：FD001/FD002 上线性模型更好，FD003/FD004 上 GBDT 更好；原因大概率是末端高 RUL 样本稀疏时，树只能"分段常数"，线性可以外推。50/50 融合在四个子集上都不吃亏，作为 W4 的候选保留。
3. **真正的难点在 FD002/FD004**：27–29 的 RMSE 说明"多工况 + RUL 分布宽（测试标签到 194）+ 高 RUL 样本少"没有被很好解决。这正是 W3（LSTM 用序列而不是窗口统计）和 W5（跨域）要回答的问题。
